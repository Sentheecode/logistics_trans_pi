# ADR 0002：物流上位机只读 MCP

状态：本机 stdio 和可选 Linux 环回 Streamable HTTP 已实现；示例网关通过本机 mTLS 验收。现场、Windows、企业统一认证和跨主机配置尚未验收。[运行与部署](../../cpp-runtime/deploy/README.md)

## 传输与授权

默认以独立低权限进程运行 C++ stdio，无监听。两种传输共用固定诊断引擎、工具参数校验和模拟工位约束。查询内容、时间范围、条数、SQLite 指令和请求体大小有上限。历史工具仅允许列明的模拟数值标签；归档与恢复是独立本机命令，不开放为 MCP 工具。序号、时间、白名单分类及计数可对外呈现；日志正文留在本机。工位范围和数据目录由部署方设定，用户输入只允许选固定模拟工位。

外部方式为单个 HTTPS Streamable HTTP 路由。管理员在 Linux 显式启用 C++ 环回后端，由 nginx 终结 TLS、以专用 CA 证书身份和序列号白名单授权至单工位。后端持私有代理凭据，并逐请求检查 Bearer、Host 和 Origin；工具再核验工位。网关和后端限制速率、并发、请求和超时，并以不含令牌和正文的记录审计。当前实现采用短连接可用的无会话 JSON 响应，无事件流推送。面向通用企业客户端的 OAuth 资源发现与统一认证是另一个部署方案，需要独立实现和验证。

## 验收与后续维护

本机用独立协议客户端验证初始化、工具清单、四项只读调用、错误参数、工位隔离和证据最小化。HTTP 再测未经授权、证书不在白名单、跨站请求、大请求及 TLS 服务端验证。实际内网启用前，先按 [部署说明](../../cpp-runtime/deploy/README.md) 在第二台受控客户端验收证书身份、HTTPS 防火墙准入、诊断退出不影响采集和回退。

维护限只读。以后如获授权，配置应用须由有权限的人批准白名单差异及版本。软件发布通过独立可信签名更新器在维护窗口试点，验证失败回退和数据保留。本模块无 shell、任意文件读写、PLC 写点、设备启停或改生产模式。

协议参考见 [MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) 和 [MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。

## 多机部署决策

Windows 目标为八台工控机各自一个 HTTPS 入口。开发机独立 Gateway 用可信配置绑定工控机 ID、端点与允许工位，双层作用域按工控机和工位审核，证书、最小授权及后端凭据按端点独立。连接策略先用有界只读轮询，单端点超时、熔断和退避不得影响其他工控机。长连接或订阅须两端明确支持。当前固定工位 MCP 没有新增主机参数、聚合进程或远程控制。按 [部署试点](../../cpp-runtime/deploy/README.md#八台-windows-工控机的内网规划) 从一台 Windows 与另一内网客户端、双机隔离验收，逐步扩大到八台。现有 Linux 环回证据仅覆盖本机合成环境。
