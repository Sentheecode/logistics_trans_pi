# ADR 0002：物流上位机 MCP 运维提案

状态：**提案，未实现或部署**。按 [C++ 迁移及旧工程清理](../cpp-migration.md) 的阶段门推进。先交付默认的本机 stdio，再交付由管理员显式启用的受保护内网访问。两种传输复用同一只读查询和授权边界。

## 本机默认

每台物流上位机用独立低权限进程提供版本、心跳、告警、按授权工位读取日志。进程退出不影响采集和 HMI。查询固定字段和工位范围，限制时间窗、条数、输出与并发；只返回必要字段，审计记操作、授权范围和结果，不记令牌或原始日志。日志正文是数据，做脱敏并禁止触发动作。默认 stdio 启动时无监听。用独立 MCP 客户端验证初始化、工具清单、工具调用、缺失和过期数据、限额、脱敏、越界拒绝及采集独立性。

## 管理员启用内网访问

从另一台内网机器访问时，使用审批后的反向代理或运维网关，提供单一 HTTPS MCP Streamable HTTP 入口。工位的 HTTP 适配器默认关闭；启用后绑定环回，使用与本机相同的诊断引擎。网关模式需要受管隧道或有双向身份校验的传输访问工位，不能把环回适配器直接映射到任意内网地址。

1. 管理员在隔离环境配置内网 DNS、受信 CA 签发的服务端证书及防火墙准入范围。只有经批准的 HTTPS 监听端口对指定管理网可见，其余诊断端口保留在本机。配置须显式启用，随后重扫监听确认默认和启用后的差异。
2. 用受审的代理、身份提供方及 MCP HTTP 适配器。面向通用 MCP 客户端时按采用的 MCP 版本实现受保护资源发现与令牌校验，验证发行方、有效期和本服务受众；网关不转发发给其他资源的令牌。强身份映射到允许的工位集合和只读权限。网关验证请求身份，工位后端验证受信、完整且短时有效的身份凭据，并逐请求检查目标工位。来源 IP 只用于网络准入。拒绝伪造的代理身份头及无效 Host/Origin。对缺省 Origin 的非浏览器客户端仍做身份认证。
3. 固定 MCP 路径；使用请求大小、速率、并发、超时与响应上限。保护传输与服务端日志，拒绝没有授权的工位、工具、字段和查询窗口。应用先由已知测试账号验证，再按维护变更流程启用。
4. 预发布至少用两个独立客户端进程。首个有工位 A 权限，完成初始化、工具清单和合法只读调用。第二个分别用无身份和仅有工位 B 权限运行，验证身份拒绝和工位拒绝，且响应不泄漏 A 的状态。同测伪造 Origin/Host、过大请求、超时、脱敏，以及另一台机器经受信 TLS 的连接。关闭入口后复查无外部诊断监听、采集仍推进。保留客户端、协议版本、TLS/身份拒绝与工位隔离结果作为部署验收证据。

当前仅确定部署步骤和验收门槛，尚无 HTTPS 地址、监听服务、网关或双客户端结果。

## 后续维护权限

维护阶段限只读诊断。配置差异预览限白名单，应用前由具备权限的人明确批准具体差异和版本。代码走仓库评审，更新走独立可信签名发布链路，在维护窗口试点并验证失败回退和工位数据保留。提案不包含 shell、任意文件读写、PLC 写点、设备启停、改生产模式或绕过联锁。

协议参考见 [MCP 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) 和 [MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。实施时固定并记录双方实际支持的版本。
