## 1. 先看这三条边界

1. **预览程序不读取本机 Excel 去连接设备。** 点表模板是编译期内置的；工作台也不把 `topology.json` 当作运行时连线配置。没有正式 PLC 地址、OPC UA 连接信息和工厂正式编码（缺口 G-01）。
2. **当前只有外装 140 绑定了模拟流。** 150、160 以及排序、仪表各站在资料上可能已有点表或布置图，但运行时并未接入，界面应写「已登记点表、未接入」或「已有布置图、点表仍缺、未接入」，不能写成已绑定。
3. **资料冲突不是软件故障。** 下文章冲突、同址、同构复制，一律待业务/电气确认，不能据此改程序或当作联调接口。

## 4. 2026-11-25 新增的布置图与交接表（能证 / 不能证）

相对此前基线，目录新增 19 个文件：图片 6、机械表格 13。13 份交接/过程表均为「设备说明 / 动作流程 / 动作时序表」。检索结果表明其中**没有**可作为接入依据的数据块或 OPC UA 地址，**不能替代** PLC-PC 点表，也补不了 G-01、G-02、G-16。

13 份全文都出现同一流程要点：AGV 拉着 3 台料车进站并到位停止；机器人带相机扫 3 台料车二维码；向料车放料后 AGV 拉 3 台料车出站。这与旧外装点表备注「三台小车公用」、以及单站轴测图的三料车形态可对照讨论，**是否同一对象仍待电气确认**。同零件同时存在带工位编号和另一份日期版文件，本轮未做逐格版本对照。

**能直接用于对照的：**

- 外装右 140/150/160 的俯视排位与零件名（150 必须保留双名称）
- 排序区 210 左、220 右及料架/使用位/缓存命名
- 仪表一 20–30–90、仪表二 40–10–70–80 的布置图零件名
- 150/160 与仪表各站的交接过程说明（进站、扫码、放料、出站）

**仍不能证明的：**

- 外装左、140 的交接表、门把手 170–200 与制动钳 230/240 的新图或新交接表
- 料车在 140–160 之间跨站行驶
- 仪表已有可接入的 PLC-PC 点表
- 正式 PLC / LWMS / AGV 联调地址

钱塘二期 AGV/上下线方案与本批车间布置图、交接表是互补资料，不能互相替代，也不能用方案图否定布置图上的 140/150/160 标注。

## 6. 程序里现在实际有什么数据

对 `297dd00` 包的静态核对（哈希、说明文件、启动脚本、程序内文案）和 Linux 实拍已经完成，**不能代替 Windows 实机界面、缩放和流畅度验收**。

已能确认的数据行为：

- 仅模拟：说明文件写明无网络监听、无现场接口、无 Windows 服务；数据目录为包内模拟数据目录
- 采集器与工作台分别启动、共用数据目录
- 外装采集页：只有 140 显示模拟源；150/160 为未接入，不出现 140 模拟帧
- 排序三/四采集页：无 140 行、无模拟帧
- 日志为独立页签，声明时间为北京时间、变化是模拟证据
- 状态栏口径应为「未连接现场设备」

旧版 `5a92900` / `274fd81` 的隔离离线命令行曾跑通（仅模拟、诊断范围是工位 140，自启进程未见对外网络连接）。那是旧版本的证据，不能写成 `297dd00` 已在 Windows 上通过。

## 7. 建议先确认的几件事

1. 第 2 节里门把手 170–200、制动钳 230/240 的候选映射，是否按 catalog 这样对应。
2. 制动钳簿与前悬几乎相同、门把手新旧表互相一致，是误复制还是尚未分地址的模板。
3. 仪表一/二只有布置图和交接过程表、没有 PLC-PC 点表，界面是否维持「点表仍缺、未接入」。
4. 交接表中的「AGV 拉 3 台料车进站→扫码→放料→出站」，与目前仅 140 绑定的三车模拟，是否视为同一对象；150/160 是否也按此流程，但先保持未接入。
5. 外装写分节同址、方向列冲突（G-08 至 G-10）以及门把手换料请求/完成同址（G-12），以哪一版电气定义为准。
