本轮约定的软件交付已实现：恢复、轮转、记录覆盖、实际分组调度、独立看门狗和受限自动重启。**T4 的现场验收仍未通过**：尚未物理拔电、未在测试工位改系统时间、未验证 Windows 文件系统/缓存。不是生产上线报告。

## 交付与证据

| 项目 | 实现/验证 |
|---|---|

| 日志量 | 常驻服务记录质量/报警变化和健康摘要，不按每次心跳翻转写普通日志 |

## 测试

完整 runtime 测试 **46 项通过、0 项失败、0 项跳过**。原始输出：`t4/evidence/runtime-tests.txt`。包含原有 mock/时钟回归，以及恢复、轮转、覆盖、缺失正文、精确计数预算、低磁盘、真实定时调度、进程监督和取消启动。

真实 SIGKILL 验证：`t4/evidence/crash-restart.json`。

| 故障窗口 | 结果 |
|---|---|
| SQLite intent 已提交、尚未写文件 | 重启导出一次，outbox=0 |
| 文件已写/fsync、索引未提交 | 重启登记完整行，不重复追加 |
| 文件只有半行 | 保存恢复副本，重建原intent，前缀不变 |
| 已知重复尾行 | 核对剩余尾部，再备份修复和重放 |
| 轮转段已标deleting、尚未删文件 | 重启完成删除与墓碑状态 |
| 主线程阻塞 | worker独立终止子进程，重新打开数据目录后完整性正常 |

六项均检查了：进程退出信号 SIGKILL、活动进程时拒绝第二写入者、重启后的高水位增加、已提交历史保留、物理日志序号唯一、outbox=0、integrity_check=ok 和外键检查。窗口通过受控故障注入构造，不能据此推导硬盘断电缓存已安全。

自动监督重启的额外证据：`t4/evidence/supervisor-restart.json`。监督者在 runtime 被杀后自动创建新 PID，历史继续增长，停止后释放子进程。该测试与“手工重新new一个实例”分开，确实经过自动拉起路径。

真实定时服务证据：`t4/evidence/service-run.jsonl`。约2.2秒运行中 100ms组21次、1s组2次、维护组2次，无错过周期/故障，健康为healthy，正常停止。这里只证明基本调度可运行，不是现场延迟或吞吐保证。

## 轮转与“查不到”

`t4/evidence/storage-demo.json` 使用明确缩小的合成策略：1200字节段目标、1秒轮转年龄、2秒保留，**不是正常90天策略**。

- 清理前窗口完整，matched_count=8，即使只返回1条也不会把总数写成1。
- 不存在的文本筛选返回 matched_count=0，窗口仍为complete。
- 清理后同一窗口只匹配到2条，覆盖partial并显示 rotated 缺口；不能解释为原窗口只有2次事件。
- 删除3个到期段，段墓碑保留，数据库完整性ok。
- 单测额外证明墙钟前跳不会提前删除年轻日志，超出查询预算不会伪装为精确总数。

正常策略、版本、每条校验、段校验、恢复 intent/完成动作与备份路径都持久保存。恢复摘要和策略进入常驻服务启动及健康日志。普通日志与审计不是一套清理逻辑，audit_events 没有接入普通日志清理。

## 现场及后续边界

1. 未执行物理拔电、测试工位系统改时钟、Windows/Node22最低版本、Windows服务注册和Electron打包。目录fsync不支持时健康降级，不伪装成已验收。
2. 没有真实OPC UA驱动/证书/NodeId，T5的24h和十次实机断网尚未开始。
3. 历史降采样与自动历史清理仍是T2的schema/策略设计，本次没有为了容量擅自删除历史。全量clock JSON、长期日志启动校验和单样本事务需要目标机规模测试与优化，未声称达到10k样本/秒。
4. 本地queryLogs尚非T6 HTTP/agent工具；只有行数预算，没有网络鉴权、分页游标、SQL运行时间限制或异步读租约。当前单写者进程中同步查询与清理不会并发交错，未来异步API必须扩展快照/读租约。
5. 日志保留按已验证运行时长而非不可信墙钟，停机时长不计，可能超过90个日历天。墓碑/恢复副本暂不自动清理，需在长期部署时配置归档容量。128GiB预算只统计JSONL正文，整盘剩余另由statfs检查。
6. 旧格式或损坏runtime.lock不会自动接管；已由新排他租约管理的进程才具备自动崩溃接管路径。未知内容/损坏确认前缀保留证据并拒绝启动，不能保证所有磁盘损坏都自动恢复。
7. 监督者自身需由OS服务管理器运行；重启预算耗尽会明确失败，不为“常驻”无限重启。无现场业务写入、前端或跨上位机共享服务被启用。

上述限制不隐藏在“测试通过”之后；T4总体状态仍是**软件验证完成，目标机/物理验收待完成**。
