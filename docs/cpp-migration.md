# C++ 替换阶段与验收表

实验分支以 `c686fcabf803a6ae53fe71f6d7c3fa78b9211b09` 为本轮可追溯基线。当前只完成阶段一的本机诊断查询切片，未达到旧后端整体替换标准。新 CLI 的正常运行无 Node、Pi、模型或旧 HTTP 服务依赖。可选 Pi 桥和 legacy 入口尚保留，不能视为最终依赖。

| 能力 | 已有 C++ 证据 | 迁移门槛与差异 |
|---|---|---|
| 采集、质量、Qt 仿真 | 独立单写者，模拟三车、断链、坏质量空值，Qt 不控制采集进程启停 | Node 的通用采集分组、订阅重建策略、源时间与时钟分段仍需对照 |
| SQLite 历史 | 专用库与 v1/v2/v3 迁移，按序号读取，新增按接收时间半开窗口 | 旧库格式并未转换；事件时间、数字聚合、桶覆盖、时钟修正未迁 |
| 日志与轮转 | SQLite 环形保留 300 条，带审计、序号、时间与帧关联 | 尚无旧 JSONL 段轮转、校验、恢复副本、墓碑与覆盖证明，不能用行数上限冒充 |
| 心跳与看门狗 | 采集心跳、过期状态、单写租约与崩溃恢复 | 尚无独立超时看门狗、拥有子进程的有限自动重启；需单独验证 Linux/Windows 语义 |
| OPC UA 只读 | 本轮未改旧 Node 适配器，C++ 仅模拟 | 选定可重复构建的成熟 C++ 依赖并确认许可、固定版本与安全设置；仅在环回合成 fixture 验证。本轮没有引入或验证该依赖，禁止用模拟代替协议验收 |
| 旧工具与 HTTP | 显式 legacy 路径，旧 Node 回归对照仍可运行 | 新 CLI 不实现 HTTP 契约。删除前须明确哪些语义已迁，哪些兼容入口经确认退役 |

## 五项只读诊断契约对照

Legacy 由 `agent/diagnose.sh --legacy` 选用旧 Node 本机 HTTP、token 和原请求响应。该切片对照测试继续覆盖五个旧工具。默认可选 Pi 桥只注册 `read_simulation_snapshot`，不注册同名兼容占位。新 C++ CLI 始终固定 SPS 单模拟流 `stn.140`，不给查询者提供任意 SQL、文件或站点参数。它报告采集心跳和帧自身的新鲜度。旧工具按各自契约使用点位、设备和时间字段，不能把最新已知值当作当下设备保证。

| 旧调用与输出 | C++ 本机替代 | 尚不可用 |
|---|---|---|
| `query_tags(tag_ids)`，每点最后值、时间、质量及缺失 ID | 模拟帧中的三车状态、源时／接收时、质量与心跳 | 任意标签、逐点最后采样、缺失 ID 语义 |
| `query_history(tag_ids, window, resolution, limit)`，按事件时间原始或桶聚合 | `window-json` 按接收毫秒查保留帧，`snapshot-json` 取保留尾部 | 标签筛选、事件时间筛选、1s/1m/1h 聚合、覆盖及游标 |
| `list_alarms(condition, acknowledgement, limit)`，独立报警记录与确认状态 | 帧上的已观察模拟报警条件 | 独立报警事件列表、条件筛选、确认与抑制状态 |
| `search_logs(window, device, tag, event_code, text, limit)`，字面匹配、精确总数、覆盖缺口 | 本实例保留日志尾部或接收时间窗、日志序号与可选帧关联 | 设备等筛选、字面检索、精确总数、已覆盖区间和缺口 |
| `correlate_time_window(window, tag_ids, device_ids)`，按接收时关联并报告覆盖 | 快照同一读事务返回帧与日志，日志可带帧序号 | 任意点／设备的跨源关联与覆盖证明 |

窗口查询限制 24 小时、固定 SQLite 指令预算、每类输出最多 40 条。保留窗口的 `has_more` 只针对可读保留记录，不报告已轮转记录或完整时间覆盖。过预算返回失败。坏质量值为 null，旧 schema 无日志表报告不可用。历史窗口始终标记为非当前证据。可复制调用见 [本机诊断](../agent/README.md)，实测见 [验证记录](../cpp-runtime/VALIDATION.md)。

## 接手顺序

1. 用合成回归补齐事件时间、聚合、覆盖、日志恢复与轮转、独立看门狗及有预算的重启，再验证只读 OPC UA 环回方案。对照以上五工具，明确验收或退役每个兼容语义。
2. 证据齐备后从实验分支删除被替代的旧工程，保留迁移记录与可追溯 SHA。现阶段仍需要旧工程作为未迁能力的实现和对照，未删除。无需修改 main 或历史。
3. 然后实现 [本机 stdio MCP 提案](adr/0002-logistics-mcp-operations-proposal.md) 的只读阶段。当前没有 MCP 进程、工具、端口或远程部署。
