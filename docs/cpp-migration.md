# C++ 迁移与旧版追溯

[当前快速开始](../README.md) 使用 C++，不需要 Node、Pi、旧 HTTP 或模型服务。主线提供模拟采集、Qt 工作台、本机 CLI 和只读 MCP。发布契约和业务资料继续记录各自原有边界。

## 能力与保留原因

| 能力 | 当前 C++ | 旧版边界 |
|---|---|---|
| 质量、状态和报警 | 独立单写者、坏质量空值、心跳与最新证据、新鲜度、模拟报警条件 | 通用标签和阈值报警、逐点时间序列及确认语义仍由旧实现对照 |
| 历史 | v1–v4 SQLite，接收时间明细、事件时间模拟帧聚合，窗口和查询有上限 | 逐标签数值聚合、跨时钟段、精确覆盖、旧库原有格式保留在旧栈 |
| 日志与恢复 | SQLite 事务保留和淘汰统计，已验收 SQLite 一致性备份恢复；MCP 仅白名单元数据 | JSONL 分段完整性、备份恢复和时间覆盖仍保留在旧栈 |
| 独立监督 | Linux 看门狗、子进程回收和有界重启 | Windows 监督及生产服务待验证 |
| OPC UA | open62541 可选环回只读 fixture，验证 Read、加密订阅、信任拒绝和模拟服务重启后重新订阅 | 采集链路中的通用驱动、订阅重建策略和现场证书配置仍保留在独立旧驱动；C++ 产品采集用模拟数据 |
| 诊断 | 原生 CLI 和四个 MCP 工具，固定单工位、独立权限边界 | 旧 Node HTTP 五工具仍可单独运行；两套接口使用不同的数据目录和语义 |

当前 MCP 的 `status`、`alarms`、`logs`、`history` 面向单模拟工位。MCP 读不到记录时仍返回覆盖未知。报警条件、保留快照和历史滚动窗口无法提供跨工位诊断、逐点查询或旧五工具输出兼容。

## 已移除与历史验证

已撤销两套 Pi 包装器和启动脚本，清理 Pi 安装锁文件、旧环境报告及已完成的 T3–T5 实施计划。对应代码、命令与证据可在 [旧版基准 0d1a429](https://github.com/Sentheecode/logistics_trans_pi/tree/0d1a429968240060a5e05a427a5816f0977fbb5d) 独立检出。原 C++ CLI 保留，桥接用例由原生 MCP 端到端测试替换。

[旧 Node 栈](../runtime/README.md) 保留尚无等价的能力和兼容测试。确需复验独立 Node 路径时，在源码根目录执行 `npm test --prefix runtime`。旧 SQLite、JSONL 和现场数据均不参与 C++ 构建与迁移。
