# C++ 迁移与旧版追溯

[当前快速开始](../README.md) 使用 C++ 采集、Qt 工作台、本机 CLI 和只读 MCP。运行、构建和当前回归不依赖 Node。旧版代码、脚本、SQL 和证据在 [固定基准 89fae7b](https://github.com/Sentheecode/logistics_trans_pi/tree/89fae7b32595dc734f6bf173a393670cc2b1b086) 可追溯；业务来源和已发布的契约文件继续保留。

| 能力 | 当前实验分支 | 差异与验收 |
|---|---|---|
| 质量、报警、心跳 | 独立单写者，分开报告最新观测和实际新鲜度；坏质量值置空，报警为模拟条件 | 没有通用阈值配置或报警确认。核心、Qt、MCP 证据回归 |
| 历史聚合 | 事件时间帧计数、两项固定合成数值标签的 min/max/avg | 不处理任意采集标签、跨时钟段或完整覆盖；坏质量和不完整状态不纳入数值。乱序、时间边界、有效零、坏质量及 CLI/MCP 输出对照 |
| 日志及归档 | SQLite 事务保留和淘汰统计，独立本地工具完成一致快照与恢复 | 原 Node SQLite/JSONL 分段、墓碑及覆盖证据留在历史；未提供旧格式导入。实测运行中备份、恢复继续采集、拒绝覆盖和拒绝异种库 |
| OPC UA | 可选 open62541 环回验收，批量读取多类型和多质量状态，加密订阅和重建 | 仅模拟 fixture。没有通用生产驱动、自动分组调度、真实端点或证书配置。环回普通 Read 和临时证书测试各自验证 |
| 诊断 | CLI 和四项 MCP 工具，当前仅一个模拟工位 | 旧五项 HTTP 接口明确退役。在 stdio、HTTP、nginx mTLS 验证工具权限、未认证和跨站拒绝 |
| 独立监督 | Linux 限额重启、采集独立于工作台和诊断 | Windows 服务或厂区部署未验收，Linux 故障注入验证重启及资源回收 |
