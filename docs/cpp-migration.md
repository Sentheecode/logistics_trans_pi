## 五项只读诊断契约对照

Legacy 由 `agent/diagnose.sh --legacy` 选用旧 Node 本机 HTTP、token 和原请求响应。该切片对照测试继续覆盖五个旧工具。默认可选 Pi 桥只注册 `read_simulation_snapshot`，不注册同名兼容占位。新 C++ CLI 始终固定 SPS 单模拟流 `stn.140`，不给查询者提供任意 SQL、文件或站点参数。它报告采集心跳和帧自身的新鲜度。旧工具按各自契约使用点位、设备和时间字段，不能把最新已知值当作当下设备保证。

| 旧调用与输出 | C++ 本机替代 | 尚不可用 |
|---|---|---|
| `query_tags(tag_ids)`，每点最后值、时间、质量及缺失 ID | 模拟帧中的三车状态、源时／接收时、质量与心跳 | 任意标签、逐点最后采样、缺失 ID 语义 |
| `query_history(tag_ids, window, resolution, limit)`，按事件时间原始或桶聚合 | `window-json` 按接收毫秒查保留帧，`snapshot-json` 取保留尾部，`rollup-json` 按事件时间统计保留模拟帧 | 标签筛选、逐标签原始事件时间明细与数值聚合、覆盖及游标 |
| `list_alarms(condition, acknowledgement, limit)`，独立报警记录与确认状态 | 帧上的已观察模拟报警条件 | 独立报警事件列表、条件筛选、确认与抑制状态 |
| `search_logs(window, device, tag, event_code, text, limit)`，字面匹配、精确总数、覆盖缺口 | 本实例保留日志尾部或接收时间窗、日志序号与可选帧关联 | 设备等筛选、字面检索、精确总数、已覆盖区间和缺口 |
| `correlate_time_window(window, tag_ids, device_ids)`，按接收时关联并报告覆盖 | 快照同一读事务返回帧与日志，日志可带帧序号 | 任意点／设备的跨源关联与覆盖证明 |

窗口查询限制 24 小时、固定 SQLite 指令预算、每类输出最多 40 条。保留窗口的 `has_more` 只针对可读保留记录，不报告已轮转记录或完整时间覆盖。过预算返回失败。坏质量值为 null，旧 schema 无日志表报告不可用。历史窗口始终标记为非当前证据。事件桶最多 120 个，刻度与 UTC 对齐，空桶省略，覆盖固定为 unknown。日志淘汰计数从 v4 起计算，不能重建此前的淘汰量或缺口时间。可复制调用见 [本机诊断](../agent/README.md)，实测见 [验证记录](../cpp-runtime/VALIDATION.md)。
