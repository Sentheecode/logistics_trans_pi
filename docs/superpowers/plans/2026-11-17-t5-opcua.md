# T5 OPC UA Adapter Implementation Plan

> **For agentic workers:** 当前执行者在已授权范围直接实现；现场连接参数待用户补充，本地模拟UA server不替代24h测试工位验收。

**Goal:** 在已有通用driver抽象之后，实现只读OPC UA采集适配、订阅健康检测与按清单恢复。

**Architecture:** runtime/drivers/opcua 独立依赖树，node-opcua精确锁定2.187.29。协议对象不离开适配层；外部只有普通样本、状态、诊断。库自动重连关闭，由驱动串行管理连接/Session/Subscription，并以心跳变化验证订阅活性，主动重建完整清单。

**Tech Stack:** Node >=22.19，node-opcua 2.187.29，node:test；registry.npmmirror.com，忽略安装脚本。

**Spec:** 用户T5与contracts/driver.ts；T4未通过物理验收，LLM仍暂缓。

## Global Constraints
- 不连接未知现场、不发PLC写、不编造NodeId；只启用已配置NamespaceUri绑定。
- 默认安全策略，不默认自动信任未知证书；Security None仅显式允许的回环测试地址。
- BadCertificateTimeInvalid先提示检查双方时钟，不直接认定证书过期。
- snapshot/diagnostic不包含凭据、私钥或node-opcua对象。
- 现场24h/十次断网与Windows仍作为未验收事实。

## Review Focus
- Session看似正常但没有数据：健康心跳必须有进展，不能仅靠TCP状态。
- 旧订阅回调在重建后到达：代数隔离，不能污染新一轮。
- 库或服务器修订采样/发布参数：显式记录请求与实际值。
- 坏质量/null/Int64大值/源时间为零：不能变成0或丢精度。
- 断开/取消与正在恢复并发：串行资源清理，不留下后台重连。
