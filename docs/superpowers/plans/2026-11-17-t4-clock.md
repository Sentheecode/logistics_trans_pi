# T4 Clock Discontinuity Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. 用户已授权继续，由当前执行者直接执行，不为纯 mock 新设业务确认。

**Goal:** 墙钟前跳/后跳后，样本仍按持久序号排序，时钟段和日志显式反映不连续。

**Architecture:** 纯 ClockTracker 预计算变更，不在预计算时提交状态。历史、时钟事件、clock state、日志 intent 同 SQLite 事务；事务提交后更新内存状态。重启切换 boot 边界，不跨 boot 比较单调值。仅增加 mock 的时钟注入入口，不修改系统时钟。

**Tech Stack:** 原生 Node/SQLite，无 npm 新依赖。

**Spec:** 用户 T4、docs/T2-data-model.md 与 contracts/runtime-v1.ts。

## Global Constraints

- 零 LLM、无 PLC 连接、不更改原始点表。
- 墙钟不被“修正”为单调；持久 sequence 决定记录顺序。
- 不将本次样本注入冒充系统改时钟或物理掉电验收。

## Review Focus

- 同 boot 单调时间倒退必须拒绝。
- 墙钟回跳与正常稀疏采样不能混淆。
- 失败事务不能消耗内存里的时钟状态。
- 重启和大序号不能倒退或丢精度。
- 源时间与接收墙钟不同，不能悄悄覆盖 SourceTimestamp。
