# T3 Mock Driver Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. 本次由当前执行者直接实现；用户已授权继续，不为已授权的 mock 工作另设业务确认门槛。

**Goal:** 不连接 PLC/LLM，跑通 mock 变化、报警、SQLite 历史和 JSONL；人为断线后按订阅清单重建。

**Architecture:** Driver 仅产出通用样本及三层状态，无数据库或 pi 依赖。MockLoop 消费样本并将历史、报警与日志 intent 同事务保存；日志另行追加/fsync。手动时钟驱动 mock，实际定时调度、健康检测与崩溃恢复归 T4/T5。

**Tech Stack:** Node >=22.19，ES modules、node:test、node:sqlite、node:fs；无 npm 运行依赖。当前环境 Node24 的验证不能代替 Node22/Windows 验证。

**Spec:** 用户 T3 验收要求、contracts/runtime-v1.ts、db/001-infrastructure.sql、docs/business/point-table-v0.1.md。

## Global Constraints

- runtime 零 LLM 依赖；不加载 pi。
- 不导入现场点表，不实现扫码写入，不连接外部设备。
- OPC UA 对象不能出现在通用 driver 接口；S7 不实现。
- 三层连接状态、频率分组、质量、订阅清单、死区和源时间优先级必须可核对。
- 每次变更有 Git 回滚点，执行结果与限制写入报告。

## Review Focus

- 链路恢复但订阅未恢复：不得产生假数据，显式 stale。
- 微小值变化同时质量变坏：质量变化不得被死区滤掉。
- 配置外部被修改：不能静默改变已保存订阅清单。
- 源时间缺失/为零：按 null 语义回退，不用真假值判断。
- 存储或日志错误：抛出错误，不声称全部数据已落盘。
