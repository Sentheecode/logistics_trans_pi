# 点位表结构 v0.1

依据 2026-11-17 用户澄清：地址拆字段；读写可以同一行；code 在名称之前；大部分同偏移属于同一功能，不能把“大部分”理解为全部。以本文件替代此前“不同物理地址必须拆成两条配置行”的建议。

## 列结构

配置表一行代表一组逻辑关联的点位，可只读、只写或两侧都有。读写两侧各自保留类型、长度、名称与来源引用，避免合并后丢失“机器人心跳/PC心跳”等差异。

| 列 | 类型/口径 |
|---|---|
| id | 内部主键，不充当现场功能编码 |
| code | 文本，排在 name 前；用户尚未提供编码值/规则，草稿允许空，保留前导零 |
| name | 功能名称；配对两侧各保留原始名称 |
| plc_id、station_code | 所属 PLC、工位；共享点范围以后明确，不复制成多个独立写入者 |
| read_name | 原始读取名称 |
| read_db | 整数，如 1900 |
| read_offset | 文本，如 `0.1`、`10.0`；不可存浮点 |
| read_type | 来源类型，如 BOOL、int、string；类型标准化另存映射，不改来源值 |
| read_length | 正整数，按原表保留；各类型长度单位待明确 |
| read_reserved | 该侧是否预留 |
| write_name、write_db、write_offset、write_type、write_length、write_reserved | 写入侧独立列，口径同上 |
| read_source_row_id、write_source_row_id | 引用来源行，不丢失原始分节和方向 |
| pairing_status | 单侧/候选/已确认；不由偏移相同直接升为已确认 |

读取侧或写入侧没有点位时，整组字段为空，不填 0、不伪造另一侧地址。预留状态按侧保存，例如读取为真实功能而相同偏移的写入侧是预留时，不把整行误判为预留。

完整方向仍以来源为准。写入列的存在仅表示该行在来源写入分节中的位置，不代表地址已获写权限。运行时仍应检查 OPC UA 映射与访问能力、资源安全分类和业务白名单。

## 配对及地址规则

- 同 PLC、同工位、同偏移是优先配对线索，不是唯一键，也不是握手协议。
- 不同偏移也允许按真实业务功能人工关联到同一行；不因偏移不同禁止配对。
- 相同偏移但功能/类型不同不能机械合并。例如读取“报警 代码”与写分节的“小车取料次序2”都写成 `8.0`，不能仅按偏移合并。
- 心跳 `DB1900.DBX0.1` 与 `DB1901.DBX0.1` 可作为格式示例；该示例不包含周期、写值、复位或运行授权。
- 用户要求严格按给定点表。因此来源写入分节的补料完成等 DB1900 **原样保留**，不能自动改 DB1901，也不按分节标题静默改 source_direction。
- 用户说明了 DB1900 只读、DB1901 写入的总体约定，但来源字段存在例外/冲突。配置保存与自动写权限分离：在未明确修订前，不能因为把 DB1900 放在 write_db 列就向它写入。当前不生成运行写配置，不反复要求用户现在改源表。
- 本表的 DB/offset 是用户要求的配置表达；OPC UA NodeId、NamespaceUri、服务端数据类型与 AccessLevel 单独映射，不拼造 NodeId，不启用 S7。

## 文件与边界

- `data/baselines/station-140.csv`：完整来源基线，不修改，仍为 116 行。
- `data/templates/point-table.csv`：新列结构格式示例，仅含心跳配对候选、单侧读码结果、来源有冲突的补料行；不是整张 140 点表的最终配对结果。
- `contracts/point-table.ts`：同一行两组列的类型表达，尚未成为数据库迁移或运行配置。

code 在示例中留空，不借用旧项目 FunctionCode，不把来源行号或 DB 地址冒充业务编码。正式 code 的唯一范围尚未明确，当前不擅自加“全厂唯一”约束。process 与 tag 的关系仍待用户继续提供；不把每行 code 自动等同 process code。
